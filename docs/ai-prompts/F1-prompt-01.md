## What the feature does

Only verified university members may register. A person registers with their
university ID number and a password. The system checks the ID against the
university records (simulated by a JSON file with about 5 fake people covering
all roles; one has only a mobile number, one has no contact details), sends a
one-time password (OTP), and activates the account when the correct OTP is
entered. The account gets the role stored in the records.

Roles: student, faculty, maintenance_staff, supervisor, administrator.
Account statuses: pending_activation, active, locked.
OTP statuses: valid, used, expired, invalid. OTP purposes: registration,
password_reset (the second one is used later by another feature, but build the
model so it can hold both).

## Business rules (exact)

- OTP: 6 digits from the `secrets` module, valid 5 minutes.
- Store only a hash of the OTP (never the plain code) and compare in constant
  time. Passwords are stored with Django's password hashing.
- Wrong OTP: rejected, the user may try again. The 3rd wrong attempt for the
  SAME OTP makes it invalid; the user must request a new OTP.
- Expired OTP: rejected, the user may request a new OTP.
- Requesting a new OTP cancels the earlier valid OTP immediately, so only ONE
  OTP is valid at a time.
- At most 5 OTP requests per 15 minutes per user. The next request is rejected.
- Minimum password length: 8 characters.
- The OTP goes to the email in the records; if there is none, to the mobile
  number.

## Acceptance criteria (Given-When-Then). Implement ALL of them.

1. Given I am not registered and my ID exists in the records, When I enter my
   ID and a password and submit, Then the system sends an OTP to my email or,
   if no email is on record, to my mobile number.
2. Given I received the OTP, When I enter the correct OTP within 5 minutes,
   Then my account is activated with the role stored in the records and I can
   log in.
3. Given I enter a wrong OTP, When I submit, Then it is rejected and I can
   enter the OTP again.
4. Given I have entered a wrong OTP 3 times for the same OTP, When I submit
   the third wrong OTP, Then that OTP is marked invalid and I must request a
   new OTP.
5. Given I enter an expired OTP, When I submit, Then it is rejected and I can
   request a new OTP.
6. Given I have a valid OTP, When I request a new OTP, Then the earlier OTP is
   cancelled immediately and the new one is sent.
7. Given my ID is not in the records, When I try to register, Then show
   exactly: "IUB ID number not found. Please contact the university administration."
8. Given an ID is already registered and activated, When I register again,
   Then show exactly: "This ID is already registered."
9. Given a password shorter than 8 characters, When I submit, Then show
   exactly: "Password must be at least 8 characters."
10. Given my ID is in the records but has no email and no mobile number, When I
    try to register, Then show exactly: "No contact details are registered for
    this ID. Please contact the university administration."
11. Given I have requested a new OTP 5 times in 15 minutes, When I request
    another, Then show exactly: "Too many requests. Please try again in 15 minutes."
12. Given my account is waiting for activation, When I register again with my
    ID and a new password, Then a new OTP is sent and my earlier password is
    replaced by the new one.
